# 开放场景目录与兼容发布

## Why

现有目录和消费者以 108 场景、18 家族、每类 6 项、12 Recipe 的固定计数校验，无法安全扩容。
需要把数量约束换成版本、唯一性、引用和资源边界，并为开放路由提供结构化知识合同。

## What Changes

- 新增版本化 v2 目录，承载场景、多维标签、领域、横向制作需求、Recipe、来源与证据边界。
- 保留已发布 v1 资源路径、108 个 ID/例文及其行为基线；v2 通过独立入口显式消费。
- 新场景可关联多个来源和领域；步骤只引用语义类型，不携带可执行脚本或授予权限。
- 为生活 Vlog、课程多版本、婚礼多交付定义知识与验收映射，配合插件编译规格。
- 扩展属于 opt-in 新合同；不把新增字段直接灌入 v1，不删除旧版限制来假装兼容。

## Capabilities

### New Capabilities

- `open-scenario-catalog`: 数量解耦、稳定身份、版本协商、安全引用与锁定消费。
- `scenario-recipe-contract`: 场景、策略、步骤要求、来源和三条代表链的知识合同。

### Modified Capabilities

无。原 `video-planning-examples` 的固定种子要求保留在 v1；本次新增 v2 适用范围。
已有变更尚未归档，不修改其已完成产物或把本次增量混入历史验收。

## Impact

后续实施涉及规划技能、内容验证器、schema/fixture、发布清单和消费者兼容测试。
配套插件变更为 `add-open-workflow-compiler`，插件负责运行时合同与执行，不在 Skills 实现引擎。
目录合同以本变更为事实源；既有覆盖研究仅作设计输入。

非目标：本轮只产出规格；不新增几百篇例文、不调用模型、不修改发布锁、不提交或发布。
未来是否获得真实剪映和三宿主证明仍独立验收，不能由目录通过代替。
